# キャリア第2レポートのレビューと2D・3D解析の試行

日付：2026-10-24。対象：[carrier main 7929491](https://github.com/airpocket-soundman/tab5-tang-primer20k-carrier/tree/7929491)、第2レポート `site/hdmi-simulation-r2.html`。前回対象は `6450c42`。回路・配線の是正は `9b24caa`、レポート分離は `33485e9`。

修正担当への具体的な作業順・対象・完了条件は[修正指示・開発引き継ぎ](CARRIER_R2_AUDIT_HANDOFF_2026-10-24.md)を参照。

## 判断

前回のESD端子内部導通に依存した断線問題は、銅ストラップ追加で是正されている。499Ωの枝も大幅に短縮され、再計算で第2レポートの数値を再現できた。一方、**実配線と解析モデルに残る差、未照合の部品ランド、複合条件の余裕を確認してから製作判断へ進む**。

2D解析と3D解析の実行環境・再現手順は用意できた。2Dの対象断面は細分化で概ね安定した。3Dは単純な直線モデルでも2D基準と約11%の差が残るため、基板全体の合否判定には採用しない。3Dソルバの実行と、物理的に妥当なモデルの検証を区別する。

今回のHDMIレビューは外部出力についてのもの。Tab5内蔵LCDへのMeOS GUI表示、PARLIOの双方向DMA、電源保護全体の適合確認を代替しない。

## 指摘と必要な対応

### 1. 製作前：ESDの実部品ランドを照合する

DOWO DFN2510-10LをKiCad標準USON-10で代用していることは、第2レポート自身も未解決事項としている。銅の連続性は修正済みだが、実部品の端子配置・推奨ランド・パッド寸法・GND・NC・実装方向の適合は別の確認。照合記録とフットプリント修正の要否を残す。

### 2. 解析モデル：Core側ソケット引き出し線がroleから欠落

PCBを再抽出すると、Core側8信号すべてで実トラック長が `tmds_roles.json` の主経路より2.4mm長い。例えばD0Pには、J4.130の中心から外へ出る幅0.127mm・長さ2.4mmの線があり、roleはその先の幅0.2mmの線から始まる。J4パッドは長さ約2mmで、この差分にはパッド内の領域も含まれる。2.4mm全体を独立した細線とみなして単純追加するのも適切ではない。

主経路はroleを優先するため、`tmds_geom.json` に線があっても現在のSパラメータ計算には自動で入らない。**ソケットパッドと引き出しの遷移領域を明示的に扱い、全PCBトラックを主経路・枝・パッド内・除外へ分類して網羅性を検査する**。影響の数値は今回未評価であり、現在の結果が何dB変わるとは断定しない。

根拠：`tmds_channel.py:segs()`、`route_pcb.py:add_escape_stubs()`、[長さ照合データ](reviews/carrier-r2-2026-10-24/numeric.json)。ソケット接点のL/Cを0とした近似とも区別する。

### 3. 解析モデル：P/Nの抵抗枝を同じ位置へ合成している

`tmds_sparam.py:channel()` はP/Nの枝アドミタンスを直列合成し、P側のtap位置へ一つの差動シャントとして挿入する。D1では推定tap座標がP=(100.823,16.015)、N=(105.050,17.335)mmで異なる。「実長・実位置を反映」は枝長については成立するが、独立した二つの接続位置を再現していない。

差動のみの近似として扱うなら適用範囲を明記する。非対称な分岐・層変更について評価するには、P/Nを保持した多導体回路／混合モードモデルか、検証済みの局所3Dモデルが必要。現時点ではモード変換を評価できていない。

### 4. 感度：厳しい条件を同時に振ると自主目標を外れる

レポートのCore85Ω、ESD0.5pFは個別の感度試験。両者を同時に設定し、他は同じモデルで再計算した。

| ペア | SDD11の最大（～1.5GHz） |
|---|---:|
| D0 | −9.90 dB |
| D1 | −9.43 dB |
| D2 | −10.33 dB |
| CK | −10.44 dB |

D0/D1は自主目標−10dB以下を外れる。この仮定が実機で同時に起きる確率や、表示の可否を表すものではない。また720pのNyquist近傍だけの値とも異なる。単独感度をもって十分な余裕があると判断せず、積層・部品容量・Core・接点寄生の組合せ条件と、PoCで許容する不確かさを明記する。

### 5. 残る近似と文書の整合

- 全層を同じ表面マイクロストリップ断面で置換している。特に内層・裏面・ビア・リターン経路は実構造の確認が必要。これはレポートで開示済みの制限。
- 抵抗枝は最大11.5mmで、数mm以下の目標は一部未達。短縮は有効だが「全項目完了」としない。
- `kicad/README.md` のStatusに旧SDD値が残る一方、Known issuesは第2版の値。対象SHAと帯域をそろえて更新する。
- 導通スクリプトはFAILED表示でも終了コード0になる。自動ゲートにはJSONの `ok` と、意図した端子対応を検査する。上下の見た目だけで極性の合否を決めない。D2の意図した反転はRTL制約へ別途記録する。

## 2D解析の実行

対象：表面差動配線、幅0.2mm、間隔0.13mm、基板厚方向のGND距離0.2104mm、銅厚0.035mm、比誘電率4.4。既存の準静電界ソルバで実行した。

| メッシュ間隔 | Zdiff |
|---|---:|
| 0.02104mm | 101.66Ω |
| 0.01052mm | 103.42Ω |
| 0.007013mm | 103.25Ω |

最後の2条件の差は約0.16%。この断面では概ね安定している。ただし格子に対する導体境界の丸めがあり、基板全体の精度・他の断面・材料公差の保証ではない。

既存のセル平均勾配によるエネルギー積分と、離散化に対応するリンクエネルギーによる積分も比較した。0.01052mm格子でZdiffは103.42Ω対102.46Ω（約0.9%差）。現状の丸め・離散化誤差として管理し、「103Ω」を小数点以下まで確定した設計値とは扱わない。ソルバ本体を上書きせず、監査用の別モジュールで計算した。

## 3D解析の実行

[公式手順](https://docs.openems.de/en/latest/install/manual_install.html)に沿って、openEMS0.37.0 / CSXCAD0.7.0 / Python3.13.17を独立した環境へ導入した。PCB・Core・ソケットを含む全体3D解析は今回行っていない。

### 既存モデルの再実行

`openems_test_single.py 0.3 0.15` を実行。約35万セル、30,000ステップ、ソルバ約107秒。表示されたZ0平均は51.2Ωだったが、終了時の残留エネルギーは約−20.6dBで、指定の−40dBに到達せずステップ上限で終了した。励振長に比べた最大ステップ数の不足も警告された。**この結果は較正合格として使えない**。

補助コードの `pml_cells` 引数は境界設定へ反映されず、実際は全境界MUR。`openems_test_pair.py` は単一励振のSパラメータ列を保存するが、差動インピーダンスの合否確認までは実装していない。これらは改善対象。

### モードポートによる別の基準モデル

公式MSLチュートリアルを参考に、均一な直線配線、基準面を線路内部に置いたMSLポート、伝搬方向PML、損失なし、厚さ0のPECで別の基準モデルを作った。物理基板の35µm銅厚モデルとは区別する。基準の2Dも同じ厚さ0として計算し、59.85Ωを得た。

| 横方向メッシュ目安 | 基板厚方向分割 | 3Dから抽出した平均Z0（0.5～2GHz） |
|---|---:|---:|
| 0.04mm | 4 | 52.43Ω |
| 0.025mm | 4 | 52.81Ω |
| 0.025mm | 8 | 53.06Ω |

3条件ともエネルギー−50dBの停止条件を満たした。最後のモデルは約11万セル、27,972ステップ、ソルバ約64秒。単なるメッシュ細分化では2D基準との差約11.3%を解消していない。ポートの電圧・電流積分、金属と誘電体境界の離散化、基準面、線路長依存、解析式との比較を切り分ける必要がある。

途中で結果要約用の存在しない属性参照を修正し、保存済みの電圧・電流プローブから再後処理した。電磁界計算の再実行を装っていない。結果JSONのpostprocess_onlyと時間はその呼出しを示し、ソルバ時間は[別の実行記録](reviews/carrier-r2-2026-10-24/summary-3d.json)に記録した。

## 対応方針

1. **2Dは現時点で実行・比較できる**。実際の各層断面、基準GND、銅厚・マスク・材料条件を明示し、メッシュ依存を添えて配線幅／間隔の検討に使う。
2. **3Dも実行できるが、現モデルの較正は未完了**。単線基準で2Dと解析式への一致を確認し、長さ・メッシュ・ポート配置を独立に振る。目安として差5%以内、細分化差2%以内を今回の検証ゲート案とし、基板の規格合格値とは扱わない。
3. 基準通過後、対称差動直線と4ポート混合モードへ進む。各ポート励振または検証済みの対称性を使い、受動性・相反性・エネルギーとモード変換を確認する。
4. 次にビア、抵抗枝、ESDランド、ソケット引き出しを個別に解析する。必要箇所を部分モデルで評価し、いきなり基板全体の大規模モデルへ拡張しない。
5. モデルを確立した後も、720p60・短いケーブル・限定モニタというPoCの最終確認は実機で行う。3D較正未完了だけを理由にPoC全体へ新たな必須認証条件を追加しない。
