# メモリ使用量と削減候補の評価

2026-10-23。初回書き込みビルド（`e92f57e`＋shellの前方宣言修正）を基準に、ESP-IDF v5.4.4 / GCC 14.2.0で比較した。比較後、ユーザー指示によりサイズ最適化版をCOM22のTab5へ書き込んだ（確認範囲は末尾）。

## サイズ最適化の比較

同じソース・機能で`CONFIG_COMPILER_OPTIMIZATION_DEBUG`から`CONFIG_COMPILER_OPTIMIZATION_SIZE`へ変更。別ディレクトリ`build-tab5-size`とローカル設定`D:\tmp\meos-idf\sdkconfig.size`を使用し、通常ビルドを維持した。ビルド成功。実行性能と周辺機能の回帰は未検証のため、既定設定への採用は保留。

| 項目 | 現行ビルド | サイズ最適化 | 削減量 |
| --- | ---: | ---: | ---: |
| アプリbin | 1,139,632 B | 1,076,832 B | 62,800 B（約5.5%） |
| 静的D/IRAM（esp_idf_sizeの全体集計） | 455,356 B | 445,374 B | 9,982 B |
| FreeRTOSライブラリのフラッシュ格納寄与 | 9,586 B | 8,674 B | 912 B |
| FreeRTOSライブラリの静的RAM寄与 | 9,082 B | 8,212 B | 870 B |

静的D/IRAMにはMeOS内部ヒープとして使う196,608 Bの予約領域も含む。すべてが無駄な占有ではない。ライブラリ別合計と全体集計は境界・アラインメントの扱いが異なるため混同しない。動的PSRAMバッファやIDF側の起動時確保はこの表だけでは評価できない。

## FreeRTOS残存分

関数・データ単位のセクション化と`--gc-sections`が有効。最終ELFに`vTaskStartScheduler`や`xTaskCreate`はないが、キュー、ロック、スケジューラー状態照会などが残る。参照元にはnewlibロック、ログ、LEDC、USBシリアル、キャッシュ・DMA・周辺制御がある。クロスリファレンスには破棄されたコードの参照も含まれるため、一覧だけで実行経路とは断定しない。

newlibはFreeRTOS起動前のロック取得を実質無処理にする実装を持つ。このため「スケジューラー未起動」でも状態照会関数を参照する。MeOSの独自タスク間で既存APIが安全かは別途監査が必要。単純にライブラリを除去、またはロックを空実装へ置換する案は推奨しない。

## 優先順位

1. サイズ最適化：機能を削らずbin約61KiBと静的RAM約9.7KiBの削減をビルド比較で確認。採用前に起動・入力・表示・Wi-Fi・SSH・カメラ・WASM・フラッシュ保存の回帰確認と性能測定。
2. 日本語フォント外部化：埋め込み配列467,155 Bが主要なフラッシュ削減候補。SDからFPGA側DDR3へ読み込み、Tab5の字形キャッシュを利用する案を開発計画へ記録。RAM削減効果とは区別する。
3. アプリの固定バッファ：エディター32,769 B、ファイラー表示8,193 B＋一覧5,120 Bなどを必要時確保・終了時解放へ変更する候補。タスクのスタック・DMA要件と異なり、PSRAMへ移せるかも評価する。
4. 通信・フォント用の常駐データ：Tailscaleのpeer配列27,136 B、状態表示9,244 B、字形キャッシュ9,216 Bなどの配置・容量を評価。必要な処理なので無条件には削除しない。
5. FreeRTOS依存整理：約9KiBのため、上記より削減優先度は低い。起動・ロック・ドライバー境界を監査した上で部分的に置換する。

生成済みの未使用ライブラリをビルド対象から外しても、すでにリンク時除去されている部分なら実機の容量は減らず、主にビルド時間・ホスト側容量の削減になる。

評価データは`D:\tmp\meos-idf\size-baseline.json`、`size-optimized.json`、`main-sizes.json`、各ビルドのmap/ELFに保存。
