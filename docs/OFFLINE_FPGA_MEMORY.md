# FPGA外部メモリのホスト検証用基盤

更新日：2026-10-23

## 目的と実装範囲

GUIの画像資源・描画バッファ・フォントなどをFPGA側DDR3に保持するため、MeOSに依存しない分割転送の最小C実装を追加した。Tab5を使用せず、境界検査とエラー時の進捗をPC上の模擬メモリで検証する。副次用途のデータ退避・復元にも同じ転送手順を利用できる。

実装は `experiments/fpga-memory/` に隔離し、MeOSのビルド・ドライバ・GPIO・既存MicroPythonコードには接続していない。通信方式、FPGAアドレスマップ、コマンド番号、バイナリ形式を確定するものではない。通常ヒープやCPUから直接参照できるRAMの増設ではない。

## APIの意味

`fm_init`で外部領域の先頭・長さ・最大チャンク長・同期読書きコールバックを設定する。コールバックがない方向の操作は拒否する。`fm_read` / `fm_write`は領域内の相対位置と長さを受け取り、バックエンドには絶対アドレスと最大チャンク長以下の要求を渡す。ホストバッファは呼出側が確保する。内部動的確保・領域割当器は持たない。

範囲外と整数オーバーフローは、バックエンドを一度も呼ばず拒否する。領域末尾での長さ0の操作は許す。非0長ではNULLのバッファを拒否する。結果は状態、完了確認済みバイト数、バックエンド呼出回数を返す。利用側は変更の有無を同期し、公開構造体の設定値を同時更新しない。

初期化失敗時は既存の領域設定を変更しないため、呼出側は必ず戻り値を確認する。最大チャンク長はバックエンド呼出しの上限であり、`fm_read` / `fm_write`に渡すバッファそのものを小さくする機能ではない。小容量の作業領域で処理する場合は、呼出側が固定長タイルを反復して生成・転送・処理する。試験には17バイトの作業タイルで257バイトを生成・保存・再読取りする例を含めた。

コールバックは0でチャンク全体の成功、非0で失敗を返す同期契約。失敗したチャンクの一部が転送されている可能性は残るため、完了数には含めない。後続チャンクは実行しない。呼出側は読戻し照合・再初期化などで状態を確定してから再試行を選択する。通常データの同位置上書きは利用できても、描画コマンド・FIFO・副作用を持つレジスタへの適用を想定しない。タイムアウト、キャンセル、再試行、非同期完了、DMA、キャッシュ同期、同時実行の保護はバックエンド設計時の残件である。

## ホスト検証

基準コミット：`7562806eb9a538d5f2c8f13efcac379b47919d84`。Windows上のPython 3.12と既存Zig 0.13系コンパイラを使用した。実行例：

```powershell
python experiments/fpga-memory/run_tests.py --cc D:/tmp/tab5-zig013/ziglang/zig.exe --zig
```

C11、警告をエラーとして扱う設定、assert有効でコンパイルし、一時ディレクトリの実行ファイルを実行する。リポジトリに生成バイナリは残さない。確認項目：

- 257バイトの往復照合、31バイト分割、末尾9バイトの転送。
- チャンク長1〜33と開始位置0〜257の組合せ8,514通りについて転送数と前方領域の不変を照合。
- 範囲外、最大整数のアドレス、NULL、長さ0、読取り専用の拒否。
- 9チャンクそれぞれの書込み失敗位置と、失敗後の後続処理停止・完了数。
- 読取り途中の失敗と、完了位置以降の再読取りによる復元。
- 失敗チャンクで1バイト変更する模擬読書きでも、完了数は成功チャンクのみを数え、後続を実行しないこと。
- 17バイトの作業領域と7バイトの通信分割による、257バイトの反復保存・復元。

模擬バックエンドでは変更なしの失敗と1バイト変更後の失敗を注入する。実機の部分書込みの位置・量、通信破損、タイムアウト後の遅延完了、DDR3保持・性能を再現した試験ではない。実機、FPGA、MeOS実行環境での成立は未確認。呼出回数は分割の論理検証であり、通信帯域や遅延の測定結果ではない。

## 一定容量の作業領域による退避・復元例

`demo_memory.c`はPC上の一時ファイルにsourceとrestoredの2領域を配置する。64KiBの作業配列1個で、`index % 251`の入力生成、sourceへの保存、sourceからrestoredへのコピー、restoredの読戻し照合を行う。各段階で`fm_read` / `fm_write`を使用する。作業配列はデータ総量に比例して増加せず、OSや標準入出力ライブラリの内部バッファは別途存在する。通信分割上限は1〜65536バイト、データ総量は0〜64MiBに制限する。一時ファイルは最大128MiBとなり終了時に閉じる。

```powershell
python experiments/fpga-memory/run_demo.py --cc D:/tmp/tab5-zig013/ziglang/zig.exe --zig --mock --size 67108864 --transfer-limit 65536
```

2026-10-23のホスト検証結果：64MiBの全バイト照合成功、標準CRC32（IEEE）の読戻し値は`8d536c88`、読取り2048回・書込み2048回。0バイトではCRC32 `00000000`、転送0回を確認した。プログラムは毎回既知入力`123456789`のCRC32が`cbf43926`になることも確認する。出力JSONは`physical_link_tested: false`を必ず含む。これはファイルバックエンドの正しさを示す結果であり、FPGA帯域・レイテンシ・DDR3保持・MeOS統合の評価ではない。

標準Cコンパイラ環境では`--cc cc`を指定して`--zig`を省略する。ホスト単体試験は`run_tests.py --cc cc --sanitize`でAddressSanitizer / UndefinedBehaviorSanitizerを有効にできる（対応コンパイラが必要）。
