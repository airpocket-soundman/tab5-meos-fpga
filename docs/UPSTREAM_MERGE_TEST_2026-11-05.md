## 統合内容

19ファイルの競合を解消。上流のCardputer対応終了を反映し、
SPI microSD、モジュール選択、native DMA USB、IME排他、入力フォーカス、
ST7123表示、二重バッファと描画所有権を維持した。
上流のタッチスナップショット、OSKオーバーレイ、電力診断、スタック診断、
画像ビューア、サスペンド基盤を統合。OSK初期表示は従来どおり無効。

サスペンドは安全な停止契約のない構成をBUSYとする保守的な暫定対応。
FPGA構成の自動サスペンドは無効。共通抑止APIを追加したが、
各ドライバの停止・復帰完了を意味しない。

BMPは既存の試験済みデコーダを共有し、上流側の重複解析を除去する。
スタック試験の基準を既存の128バイトFPU保存フレームに合わせる。

## Tab5実機試験（標準large）

実機確認SHA: `f84096358cc9d52f192021e3eca7fbc79d898db0`。
CI run [41936719460](https://github.com/airpocket-soundman/tab5-meos-fpga/actions/runs/41936719460) の
`merge-tab5-large-v5.5.2`。SDK 5.5.2、native DMA USB、ネイティブM5EX許可なし、FPGA物理ゲートOFF。
BIN: 1,475,264 bytes、SHA256:
`c0f748048625cd93aaf7e9f92fe2c53ed4c297fc1f032695b9f78dd2ff50504c`。
書込み時にCOM22のUSB親識別子を照合し、全フラッシュファイルのSHA256と
書込み後のesptool検証を確認。別Tab5にはアクセスしていない。

- 起動・シェル・診断コマンド実行。パネル選択はST7121、タッチ検出はST712x。
- 保存済み設定でWi-Fiが接続。C6書換え・認証情報変更なし。
- MicroPython `print(6*7)` が42を出力し終了。
- `put --ack` でPPM 17 bytes / CRC32 `c4863657`、BMP 62 bytes / CRC32 `2f5f9421`をRAMルートへ転送。
- BMP情報は2×1、RGB565復号4 bytes、FNV-1a `669259080`、非一様と一致。
- PPMの`view`、BMPの`view`、BMPの`image`を各3回起動しQで終了。
- 開始前・各反復後・SD試験後の5回の観測で、使用量は内部92,592 bytes、
  PSRAM 8,588,864 bytesのまま。画像表示終了後の増加なし。
- 全描画スナップショットでerrors=0 / timeouts=0。最終submitted=retired=50。
- `ps`で全対象タスクのスタックガードOK、終了後も余計なタスク残存なし。
- `/sd`へ排他的に新規ファイルを作り9 bytesを書込み、別のopenで内容一致を確認して削除。
  既存ファイルの上書き・媒体初期化なし。長時間負荷・電源断耐性の試験ではない。
- `sleep`は理由付きBUSY、状態はawake / CPU360MHzのまま。実機での休止・復帰は未検証。
- RAMルートの画像テストファイルは削除。自動休止は試験中の操作でOFFにした（起動既定値変更とは別）。

最初のホスト操作ではコマンド長制限と非同期Wi-Fiログの後置により試験器が失敗した。
128文字以内のコマンド／ACK転送と、プロンプトを含む応答の判定へ直して再試験した。
これをファームウェアの合格結果として流用していない。

## CoreS3互換性の追加確認

SDK5.5.2での追加ビルドから、整数書式、Tab5専用コマンド／描画API、
タイマー定数、SDK4のPSRAMプライベートAPI参照が見つかった。
表示引数の型を合わせ、ボード条件とSDK別処理を分けた。
SDK4.4.3で使う既存のPSRAM初期化契約を残し、SDK5系は公開APIとMMUで領域を確認する。
元の`tools/env.sh`が選ぶSDK4.4.3と、追加のSDK5.5.2を別々にビルドする。
実際のCoreS3機体への書込み・動作確認は行わない。

## 残る確認と判断

- タッチのスワイプ、OSK呼出し・終了、実キーボード入力、IMEの目視確認。
- USBハブ・受信機・複数ストレージ・Ethernet・UVC、内蔵カメラの実機回帰。
- FPGAのLINK・画素一致・32/64/128/256描画・連続転送・中断・再開。
- 電源操作・クロック変更に対応する各ドライバのquiesce契約。
- 上流追加の8/32-bit BMPは今回の共有デコーダへ取り込んでいない。
  現在は既存の16/24-bit BMPとPPM/PGM。対応形式を広げる場合は共有デコーダを拡張する。

シリアル応答と描画カウンタの確認は、液晶の画素やちらつきの目視確認とは区別する。
これらの未確認項目を残すため、今回の結果だけでmainへ反映せず、統合試験ブランチに保持する。
