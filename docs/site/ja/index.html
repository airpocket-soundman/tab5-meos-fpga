Tab5 MeOS FPGA 開発計画

M5Stack Tab5上のMeOSに、Tang Primer 20Kによる描画処理と外部DDR3バッファを追加する計画です。実装状況、構成、検証項目を記載します。

基準ファーム、浮動小数点コンテキスト、microSD、USB Ethernet、Wi-Fi、SSH同時動作、タッチスクロール、内蔵カメラの基本機能を実機確認済みです。USBストレージの新転送方式での回帰試験は残件です。USBカメラとBluetooth入力は一部動作を確認し検証を継続中、FPGA・GUI拡張は今後の計画です。

開発順序と進捗

基本機能完了・実機確認済み：12項目 ／ 実装完了・回帰確認待ち：2項目 ／ 一部実装・ホスト試験済み：2項目 ／ 開発・検証中：4項目

完了は記載した基本機能の実機確認を指します。長時間試験や追加機能は残件として区別します。実装後に転送方式を変更したUSBは、回帰確認待ちとして表示します。

  1. 基準ファームウェア完了・基本機能実機確認済み

    サイズ最適化版を書き込み、起動・mem・ps・lsを確認。全機能回帰は未実施。

  2. OS基盤：浮動小数点コンテキスト完了・基本機能実機確認済み

    ESP32-P4の協調切替でFP保存レジスタとFCSR、タイマー割り込みで全FPレジスタとFCSRを保存・復元。実機タスク間分離試験とホストの配置・初期化試験に成功。全命令・全ISRの網羅検証ではない。

  3. 1. USB受信機・USBメモリ実装完了・回帰確認待ち

    独自DMA版で37・512・8192バイトの読み書き・再起動後保持を確認。再接続処理も修正し、I/O停止中の抜き差し1回で再マウント、既存全内容一致、新規512バイトの読み書きを確認。TinyUSBは比較用。受信機の直接接続と高速ハブ経由の入力も確認済み。Buffer DMA切替後のストレージ読み書き回帰試験は残件。

  4. 2. microSD完了・基本機能実機確認済み

    SPI接続、/sd FATマウント、一覧取得、新規38バイト書き込み・読み戻し・再起動後保持、/usbとの同時マウントを実機確認。高速化・抜き差しは未検証。

  5. 3. USBハブ・複数メモリ・キーボード併用実装完了・回帰確認待ち

    独自Buffer DMAへ統一し、高速ハブ配下のFull-Speed無線受信機をスプリット転送で認識。入力レポート・シェル実行をログとユーザー操作で確認。USBメモリ2本のマウント、Ethernet ping 10/10も確認。診断表示は削除。新方式での読み書き併用試験は、接続機器がなくなったため未確認。従来方式では2本のCRC付き読み書きを確認済み。

  6. 3a. USB Ethernet完了・基本機能実機確認済み

    RTL8153 CDC-ECMでリンク・DHCP・ping・SSHを実機確認。MSCのDMA待機中にUSBロックを解放し、USBメモリ2本の読み書きとping併用で各20/20応答、USBエラー・ドロップ0。長時間試験と抜き差し時の通信継続は未確認。

  7. 3b. Wi-Fi動作確認完了・基本機能実機確認済み

    C6を公式MCUアプリへSDIO更新。再起動後の維持、Wi-Fi初期化・検索・WPA2接続・DHCPを確認。LANケーブルを抜きEthernet非アクティブの状態で、Wi-FiによるDNS名前解決とHTTP 200受信を実機確認。長時間通信と再接続試験は未実施。

  8. 4. SSHサーバー・クライアント同時動作完了・基本機能実機確認済み

    共有コンソールへ接続するSSHサーバーを実装。実機で認証・コマンド実行・再接続・停止と、接続維持中のSSHクライアント実行を確認。Web/TailscaleとはTCP枠を分離。SFTP拡張を実装しホスト試験・全体ビルドに成功。独立PTY・execは未実装。SFTPの検証範囲は項目4bを参照。

  9. 4a. 共通端末・VT100／VT220／xterm対応一部実装・ホスト試験済み

    LCD/SSHに256色・RGB、スクロール領域、行挿入削除、カーソル保存復元、代替画面等を実装。SSHは問い合わせ応答とDECCKM、Vimキー透過も追加。実parserのホスト検証済み。SLは実機シリアルのANSI出力・正常完走・中断復帰を確認。Vim通し確認、SL表示の目視評価と完全なVT220/xterm互換は未達。

  10. 4b. SFTP・Linuxストレージヘルパー完了・基本機能実機確認済み

    SFTP v3エンジン、SD／USBの公開範囲制限、読み取り専用の既定方針、FATの排他的新規作成を実装。Python標準ライブラリ＋OpenSSHの単体ヘルパーはconnectで既存SSHFS／FUSEを試し、利用不可なら対話的ファイル転送へ切替。ホスト試験・全体ビルドは成功。実機のローカルSFTPエンジン試験でSDへ新規8192バイトを書き込み、読み戻し、既存EXCL拒否、その後の内容保持を確認。Wi-Fi実機へParamikoとヘルパーの実SFTPクライアントクラスでSDの102400バイト往復転送2回、既存EXCL拒否・内容保持・削除・再接続、RO一覧と書込み拒否が成功。認証前にシリアルのSHA256ホスト鍵指紋を照合。実ヘルパープロセス＋Windows OpenSSH 9でSD20480バイトput/get一致・ls/rmにも成功。ユーザーSSH設定は変更せず指紋照合済みの隔離known_hostsを使用。Linux実プロセス・FUSEとUSBのネットワーク転送は未確認。現在1受信接続のみで、Tab5発SSHを使う逆方向公開は未実装。

  11. 5. タッチ入力・コンソールスクロール完了・基本機能実機確認済み

    256行の色付き履歴、上下スワイプ、最新出力への復帰を実装。ST7121端末でユーザーがスクロールを確認。2面描画は実機で更新20回・DMA完了20回、エラー・タイムアウト0。ちらつき改善の目視評価と長時間試験は未実施。 UVC同時実行でも描画16/16完了・エラー0だが、最大更新時間1.642秒となり高負荷時の応答遅延は残る。

  12. 6. Bluetoothキーボード・マウス実装・実機検証中

    C6のSDIO HCI経由でBLE初期化に成功（ready、error 0）。3秒の受動探索で周辺2台を検出。HCI TX20／RX22、failed 0／reject 0。自動接続は行わず、ペアリング済みHID機器によるキーボード／マウス入力・再接続は未確認。Classicは別途調査。 BLE起動・探索後もWi-FiでHTTP 200・577バイトの受信を確認。現状の接続管理は1相手機器に限定。

  13. 7. USBカメラ（UVC）実装・実機検証中

    接続UVCカメラで160×120の単一フレーム取得とBMP保存に実機成功。2688バイトのペイロードとalt6を使用し、High-Speedの3トランザクション転送に対応。画像品質、連続取得、プレビュー、抜き差しは未確認。 現状は1フレーム取得に約8〜10秒を要し、不正・不完全なパケットが多く、実用的なフレームレートには達していない。 BMP読戻しで19113/19200画素が非ゼロ、値の変化を確認（FNV 9c385858）。色・向き・画質の目視確認は未実施。

  14. 8. Tab5内蔵カメラ完了・基本機能実機確認済み

    SC202CS（ID eb52）のCSI／ISP経由RGB565取得を実機確認。640×360画像をmicroSDへ460870バイトのBMPとして保存。停止・再起動・再取得も成功、DMAエラー0。画像品質、連続フレームレート、長時間動作は未評価。 BMP読戻しで230400画素すべて非ゼロ、値の変化を確認（FNV 07d53fa4）。

  15. 9. 外部GPIO・ADC・PWM・I2C・SPI・UART実装・実機検証中

    共通C APIとGPIO／未校正ADC／PWM／SoftI2C／SoftSPI／UART1のシェル操作を実装。ホスト試験・全体ビルドに成功。実機で予約ピン拒否、GPIO16入力・解放・reset、ADC16／53生値取得、UART内部ループバックに成功。ADC35は非対応として拒否。外部機器・基準電圧・PWM波形・I2C／SPI／UART配線試験は未確認。Python側は項目10／10aを参照。汎用DACは対象外。

  16. 10. MicroPython・machine.Pin／ADC完了・基本機能実機確認済み

    MicroPython v1.26.1をMeOSへ直接組み込む初期ポート、REPL・スクリプト・VFS連携、machine.Pin／ADCを実装。GCヒープはPSRAM 512 KiB、タスクスタックは32 KiB。共通IO所有権を使用し、VM終了時にファイルとピンを回収する。全体ビルド・書込みに成功。実機REPLで2**80・math.sqrt(9)・GCを確認し、GPIO16入力・ADC16/53・予約/重複/解放済みオブジェクト拒否・40回GC負荷のsmoke.pyが成功。実機SDスクリプトで隣接モジュールimport、排他的1024バイト新規ファイルの読み書き・seek/tell・closeに成功。意図的例外後のPin再確保、MemoryError後のVM再起動、無限ループCtrl-C後のシェル復帰と次VM実行も確認。初期機能の限定検証であり、長時間動作は未評価。外部出力波形は未確認。PWM／UART／SoftI2C／SoftSPI／timeの拡張は項目10aを参照。IRQとCPython・Pyxel互換は含まない。

  17. 10a. Python周辺IO・単調時刻API実装・実機検証中

    PWM、UART1、SoftI2C、SoftSPIとtimeを実装。実32ビットMicroPython VM＋IOモックで機能・例外後解放を検証（156サービス呼出し、UART受理8バイト）。実機では外部出力を行わないPWM拒否、UART設定拒否、バス23安全拒否試験とtimeの範囲・wrap・delayが成功。time.sleep(60)のCtrl-C復帰は約0.125秒。ファーム増加6464バイト。実PWM波形・UART配線通信・I2C/SPI機器通信は未確認。IRQは未実装。

  18. 11. ネイティブSL移植完了・基本機能実機確認済み

    上流SL 5.03のコード・素材・ライセンスを保持し、MeOS用最小ANSI/curses互換層とPSRAM描画・煙状態へ移植。ホスト90回超反復と全体ビルド・書込みに成功。実機シリアルで標準slが15.30秒・95329バイト出力で完走し、代替画面の開始/終了とシェル復帰を確認。sl -aFのCtrl-C、sl -lcのEscはいずれも約0.86秒で復帰し再実行成功。目視画質・LCD見え方・SSH経由描画は未評価。

  19. FPGA通信：ソフトウェア基盤一部実装・ホスト試験済み

    583件の互換ベクトル、分割・異常系とTab5上mock自己試験に合格。物理通信・GPIO・DDR3・DMAは未実装。

  20. BMP画像表示完了・基本機能実機確認済み

    image / image --infoを追加。実機で2x2 BMPの検査・表示開始・終了・RAM解放、描画エラーなしを確認。目視・大画像は未確認。JPEG/PNG未対応。

Tab5 MeOS FPGA — 開発目的と開始記録

更新日：2026-10-26

目的と範囲

主目標を、FPGAによる描画支援を組み込んだMeOSのGUI化とする。Tab5上で、ウィンドウ、メニュー、文字、画像を扱うGUIを構築し、Tang Primer 20Kとその128MB DDR3を描画処理・画像資源の保持に活用する。文字中心の操作環境から、初期Windowsのようなウィンドウ操作環境への発展を目指す。Windows互換性は要件に含めない。

MeOS側は入力、ウィンドウ管理、アプリの状態、描画命令の生成を担当し、FPGA側は矩形塗りつぶし、画像コピー、合成などを段階的に担当する。具体的な分担は転送時間を含む測定で決める。既存の上流GUI・コンソール・表示ドライバを調査し、利用できる部分を土台にする。

大容量データの分割処理、明示的な退避・復元、演算アクセラレーションは、GUI基盤と共通する転送・バッファ管理を活用する副次的な研究対象とする。

Linux版とMeOS版を別リポジトリで管理し、通信プロトコル、データ照合、評価条件を整合させる。OSごとのAPI・メモリ管理・スケジューラ・DMA対応は個別に調査する。Linux用ドライバをそのまま利用できるとは扱わない。

FPGA側DDR3は明示的に転送する外部データ領域であり、通常のCPUポインタで参照できる主記憶や透過的なmalloc領域とは扱わない。GPU用と外部RAM用の同時搭載は初期の要件とせず、資源・帯域の評価後に判断する。

GUI化の段階と評価

  1. 基準環境：MeOSのTab5向けビルドと表示経路を確認し、CPU描画の所要時間と内部RAM・PSRAM使用量を記録する。
  2. 通信とDDR3：小さなデータの往復照合から開始し、転送の安定性・実効帯域・DDR3のデータ保持を確認する。
  3. 最小描画支援：FPGA側バッファへの矩形塗りつぶしと画像コピーを実装し、Tab5画面に結果を表示する。命令送信・実行・画像回収・表示を含む所要時間をCPU描画と比較する。
  4. GUI統合：MeOSの描画APIにCPU実装とFPGA実装の切替を設け、ウィンドウの表示・移動、メニュー、文字・画像表示を検証する。画像資源の常駐と変更領域の転送を評価する。
  5. 拡張：測定結果に応じて合成、拡大縮小、追加の計算処理へ進む。

最初の到達点は、Tab5で入力操作できるウィンドウとメニューを表示し、少なくとも一つの描画処理をFPGA経由で実行できることとする。高速化の成立は別途測定で判断し、フレームレート、操作応答時間、CPU負荷、RAM使用量、転送量を記録する。

初期はTab5既存LCDへのESP32-P4経由の表示を評価する。FPGA側DDR3に画像を置いても、表示のための画像回収が帯域を消費するため、表示経路は設計上の主要な検証項目とする。FPGAからの直接表示は別途ハードウェア構成の検討が必要であり、初期の前提にしない。

USBスタックの選択（2026-10-23）

M5Stack公式UserDemoはESP-IDFのUSB Host LibraryとHIDドライバーをFreeRTOSタスクから利用している。Tab5thinclientはTinyUSBのHID・MSC Host APIを利用する。本フォークは独自ディスクリプタDMAドライバへ集約する。TinyUSB 0.19.0を参照し、ホストモード切り替え完了を待ってからFIFOを設定するよう独自HALを修正した。修正版でUSBメモリの読み書きと再起動後保持を確認。PHYの電源・クロックとDWC2 HALにはESP-IDFを使用し、FreeRTOSスケジューラーは使わない。TinyUSBのOS_NONE・FIFO版は比較用に残す。実装と検証範囲はUSB実装記録、DMA調査記録を参照。

  • カーソル移動・保存復元、画面／行消去、文字属性・色、スクロール領域、自動折り返し、DEC特殊文字を検証する。

USBカメラと内蔵カメラ

USBカメラはUVC対応を独自USB DMAドライバへ追加する計画。ハブ・複数機器対応の後に、実機のディスクリプタから転送方式、対応形式、解像度、フレームレートを調査する。バルク／アイソクロナス転送は機器に応じて実装し、フレーム境界・欠損・帯域・DMAバッファのキャッシュ同期・切断時の解放を扱う。MJPEG復号と非圧縮形式の変換は別途資源を評価し、低解像度・低フレームレートでのプレビューと保存から検証する。すべてのUSBカメラとの互換性は未確認。

Tab5内蔵カメラにはSC202CSの初期化、MIPI-CSI、ISP、DMA転送を扱う既存ドライバと撮影アプリがある。本フォークで初期化・映像表示・保存・開始停止の繰り返し・終了時の資源解放を実機確認し、不足を修正する。USBカメラとは通信経路が異なるため個別に検証し、成立後に共通のフレーム取得APIとGUI連携を検討する。

USB→microSD→ハブ→SSH→タッチ→Bluetoothの優先順を維持する。端末仕様対応はSSH段階に組み込み、カメラ2項目はその後の予定として表示する。性能・対応形式・日程は実測後に定める。
